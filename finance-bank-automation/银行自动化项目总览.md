## 系统边界（口径基准，所有文档以此为准）

本系统**只负责自动化制单 / 经办录入**，**不负责**最终审核、授权、确认或付款 / 放款。

- **默认 = 测试 / 验证模式**：使用占位数据、测试金额、只填单（fill-only）/ dry-run、截图，不产生真实制单结果。这是未显式开启生产时的默认行为。
- **正常制单模式**：仅当操作人显式选择生产入口或设置生产环境变量（招行 `ZHIDAN_TEST_MODE=0` / 兴业 `CIB_ALLOW_SUBMIT=1` / 中行 `BOC_ENABLE_ORDER_SUBMIT=1`；农行也是制单项目，需显式 `ABC_ALLOW_SUBMIT_ONCE=true` 且单条/逐条，并由 `ABC_CONFIRM_SUBMIT_MODAL_ONCE` / `ABC_CONFIRM_TRADE_INFO_ONCE` / `ABC_TRANSFER_KB_PASSWORD_AFTER_TRADE` / `ABC_OK_SERVO_AFTER_TRANSFER_KB_PASSWORD` 逐级门禁，物理 OK 仅在交易 K宝密码提交后触发、不得提前、不得默认开启）后，才完成"经办 / 制单 / 提交"，并把单据送入**银行自身的待审核 / 待复核队列，随后立即停止**。
- 系统**绝不**自动复核、自动授权、自动确认、自动最终付款 / 放款。送入待审核队列后的复核、授权、付款一律由**人工和银行系统**完成。
- 因此"提交"≠"付款"：生产模式下的"真实提交"指把单据录入银行待审核队列（maker entry），不是最终出款。
- 不得新增任何自动复核 / 授权 / 确认 / 最终付款路径，不得绕过上述生产开关，不得把生产开关预置为开启。

## 共享约定

## 提交前检查 / 风险提示

首次入库或日常提交前，运行者应逐项确认（这些是运行者可执行的检查项，不是开发待办）：

- **含真实数据的运行产物不得入库**（应已被 `.gitignore` 覆盖，提交前用 `git status` 复核确实未被跟踪）：`**/latest.json`、`**/screenshot_transfer_batch*.json`、`**/transfer_data.json`、真实网银截图 `screenshot*.png`、usbhub 运行日志 `log.txt`，以及 `__pycache__`、各项目 `screenshots/`、`debug_runs/`、`runs\balance_*` 等运行目录。
- **USBHub 厂商驱动与控制软件不得入库**（vendor 二进制，仅本机使用）：`公共\usbhub\usbhub\CH341SER\`（CH341 串口驱动 SETUP.EXE / *.sys / *.DLL / *.CAT / *.INF / *.VXD 等）、`公共\usbhub\usbhub\多口USB控制器软件以及驱动\第一步驱动包\`（CH341SER.exe 驱动安装器）、`公共\usbhub\usbhub\多口USB控制器软件以及驱动\第二步软件\`（`usbHubCtrl.exe` + `Qt*.dll` + `vc_redist.x64.exe` 等厂商控制软件）均已在 `.gitignore` 中按目录忽略；仓库内只保留 `公共\usbhub\usbhub\多口USB控制器软件以及驱动\hub_ctrl.py`（pyserial 调用约定）。换机时需要人工另行准备对应 USBHub 驱动 / 控制软件目录或按本机路径放置 vendor 二进制；不要把 vendor `log.txt`、驱动安装包、`*.dll` / `*.exe` / `*.sys` / `*.cat` / `*.inf` 提交入库。
- **切勿在源码默认值或 `.bat` 中硬编码真实收款账号 / 户名 / 登录名。** 制单脚本的占位安全闸门依赖"出厂值为占位"（例如兴业 `DEFAULT_TRANSFER` 出厂为 `acct_no="000000000000000"`、`bank="示例银行"` 等占位）。运行者**不要**用真实数据替换这些默认占位——一旦占位被真实数据覆盖，fail-closed 保护就会失效。
- **普通启动器默认不内置真实提交开关。** `run_快速制单.bat` / `run_快速制单_带Codex上报.bat` 已移除内置 `CIB_ALLOW_SUBMIT=1`，双击只填单、不提交。真实制单提交（录入银行待审核队列，非最终付款）必须由操作人先确认 `DEFAULT_TRANSFER` 已替换为真实数据，再在命令行临时设置对应提交环境变量（兴业 `set CIB_ALLOW_SUBMIT=1`、中行 `BOC_ENABLE_ORDER_SUBMIT=1`、招行 `ZHIDAN_TEST_MODE=0`）后手动运行；设置前必须人工核对目标账户、户名与金额无误并确认确属生产意图。不确定就用 de-risk 入口（兴业 `login_only.py` / `batch_fill_only.py`、中行 `--login-only` 等）。
- **USB Hub 通断电控制若串口无响应，不应继续制单。** 此时 U盾连接状态未知，必须停止流程，排查串口（`USB_HUB_COM` / `CIB_USB_HUB_COM` / `BOC_USBHUB_COM`）后再重试，绝不能在 U盾状态不明时点经办/下一步/提交。
- 提交前同时核对：真实提交/制单开关仍为默认关闭或仅在生产入口显式开启；本总览与各项目主说明是否同步；凭据仍只在未被跟踪的 `.env` 内。
