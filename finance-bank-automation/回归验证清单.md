# 回归验证清单

这份清单用于降低“改完代码后原有功能失效”的风险。默认原则是先跑快速、非破坏性检查；只有改到关键路径，才升级到 GUI 或真实银行验证。

## 分层原则

| 层级 | 何时跑 | 内容 | 是否打开银行 / USBHub |
| --- | --- | --- | --- |
| L0 快速静态检查 | 每次改代码后 | Python 编译、网关 TypeScript typecheck、危险环境变量检查、敏感产物入库检查 | 否 |
| L1 契约检查 | 改 M3 / 路由 / 门禁 / 脱敏后 | M3 只读核验、银行队列 dry-run、金额/账号/截图必填规则 | 否 |
| L2 项目内安全路径 | 改单个银行流程后 | 只跑该银行的 read-only / login-only / fill-only / test-mode 入口 | 可能打开银行，但不提交 |
| L3 GUI 验证 | 改登录、填表、支行匹配、USBHub、截图后 | 对应银行的测试模式或只填表流程，检查截图和日志 | 会打开对应银行 |
| L4 全链路验证 | 上生产前或改 M3 调度 / bank_route / 多银行主流程后 | M3 抽取 -> 队列 -> 分银行验证模式 -> 飞书摘要 | 会打开相关流程，仍应保持生产提交门禁关闭 |

## 一键快速检查

默认入口只做 L0，并在有 M3 verification 记录时顺带跑只读校验：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "C:\Users\30112\Desktop\财务\公共\maintenance\run_safe_regression_checks.ps1"
```

可选增加 M3 队列 dry-run。这个模式只校验和打印，不启动银行程序：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "C:\Users\30112\Desktop\财务\公共\maintenance\run_safe_regression_checks.ps1" -RunM3DryRun
```

`-RunM3DryRun` 会校验当前 `runtime\bank_batches` 里的实际队列。如果队列是旧数据、缺 M3 列表截图或详情截图，它会失败并提示原因；这表示当前队列不满足制单契约，不代表脚本打开了银行或执行了提交。

## 改动类型到检查范围

| 改动类型 | 最小必跑 |
| --- | --- |
| 文档、注释、说明文字 | L0，可只看相关文档 diff |
| 单个银行纯 Python 辅助函数 | L0 + 对应项目 `compileall` |
| 单个银行登录 / 填表 / 支行匹配 | L0 + L2，对应银行安全路径；必要时 L3 |
| USBHub / UKey 选择 | L0 + L2；必须人工复核端口和 all-off 规则 |
| M3 抽取字段 / 预校验 | L0 + M3 只读核验 |
| `bank_route.py` / 银行分流 | L0 + `-RunM3DryRun`；上线前 L4 |
| 网关 / 飞书上报 | L0，重点看 `npm run typecheck`、白名单、报告 token、脱敏 |
| 提交门禁 / 生产入口 | L0 + L1 + L2；上线前 L4，并人工核对所有生产开关 |

## 生产前人工复核

- 当前 shell 不应残留 `M3_PRODUCTION_MODE=1`、`CIB_ALLOW_SUBMIT=1`、`BOC_ENABLE_ORDER_SUBMIT=1`、`ABC_ALLOW_SUBMIT_ONCE=true`、`ZHIDAN_TEST_MODE=0` 等生产提交开关。
- `M3_BANK_AMOUNT_OVERRIDE` 只允许测试入口使用；生产前必须确认它没有残留。
- 付款账号、户名、金额、付款银行、M3 列表截图、M3 详情截图必须能从本轮数据核对。
- `.env`、截图、`runtime/`、`data/`、`debug_runs/`、`screenshots/`、SQLite 数据库和日志不得入库。
- 改到某个项目的入口、提交边界、USBHub 规则、日志/截图路径或清理策略时，同步更新 `银行自动化项目总览.md` 和该项目主说明。
